## Authentication

All API endpoints are authenticated using the `x-api-key` header.

## Supported chains

Most read endpoints accept a `chain` query parameter. It defaults to `SOL`, so existing
integrations need no change.

| Value | Network | Protocol |
| ----- | ------- | -------- |
| `SOL` | Solana | Meteora (DLMM, DAMM v2) |
| `ROBINHOOD` | Robinhood Chain (EVM, chain ID `4663`) | Uniswap V3, Uniswap V4 |

An unrecognised value falls back to `SOL` rather than returning an error.

These endpoints are chain-aware:

| Method | Endpoint |
| ------ | -------- |
| `GET` | `/lp-positions/opening` |
| `GET` | `/lp-positions/historical` |
| `GET` | `/lp-positions/overview` |
| `GET` | `/lp-positions/logs` |
| `GET` | `/lp-positions/position` |
| `GET` | `/lp-positions/revenue/{owner}` |
| `GET` | `/pools/discover` |
| `GET` | `/token/balance` |
| `GET` | `/pools/{poolId}/positions` |
| `GET` | `/pools/{poolId}/onchain-stats` |
| `GET` | `/pools/{poolId}/top-lpers` |

On `/pools/{poolId}/onchain-stats` and `/pools/{poolId}/top-lpers`, `chain` is optional: when
omitted it is inferred from the pool ID (`0x` IDs are Robinhood Chain, anything else Solana).

Every endpoint that filters by protocol takes it as `platform`, a comma-separated list such as
`uniswap_v3,uniswap_v4`. The older names `protocol` (overview, revenue) and `type` (discover)
are still accepted.

Every other endpoint is Solana only. The remaining `/pools/{poolId}/*` routes read Meteora
pool state, and the transaction-building, Jito, and RPC routes are Solana specific. See
[Robinhood Chain Integration](/integration/robinhood) for the response differences and
current data limitations.

| ----- | ------ | --------------------------- |
| Pools | `GET`  | `/pools/{poolId}/top-lpers` |
| RPC   | `POST` | `/rpc`                      |
| RPC   | `POST` | `/rpc/historical`           |
| RPC   | `POST` | `/jito`                     |

To upgrade, manage your API key and billing in the [LP Agent Portal](https://portal.lpagent.io/).
